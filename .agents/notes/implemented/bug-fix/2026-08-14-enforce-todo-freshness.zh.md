# Agent Note：在工具准入点强制 todo 状态新鲜度

Status: implemented

[English](2026-08-14-enforce-todo-freshness.md) | 中文

## 问题

`todo_write` 要求模型在每项完成时立即标记，不能批量补状态，但运行时此前只强制清单 schema。真实多步骤 session 会写入初始清单，跨多个已完成条目执行数十次工具，然后在接近结束时一次替换多个状态。Web 投影正确渲染了每个持久更新；缺失事实根本没有被追加。

模型省略记账调用时，仅靠提示措辞无法让任务状态可观察。运行时需要在一个有界点中断过期状态下的后续工作，同时不能猜测 shell 命令、文件编辑、subagent 或 Code Mode 程序完成了哪个任务。

## 决策

随附 base composition 在 `tool-todo` 旁挂载 `@deepseek-ai/dsh-todo-freshness-guard`。插件把当前 turn 最新的未完成 `todo/write` 视为一个新鲜度 epoch，并在 `tools/pre-execute` 预留非记账工具尝试。第 5 次尝试通过 `tools/post-execute` 附带一条插件来源提醒；前 8 次尝试可以完成，之后的尝试会被拒绝，直到另一个成功的 `todo_write` 替换完整清单。这些值复用现有循环卫生升级区间，并在提醒后保留三次纠正机会。

计数在执行前的准入阶段递增，因此并行调用不能针对同一个过期计数全部放行。提醒预留会保留 epoch 对象；并发 `todo/write` 会替换该对象，并在较早工具结束时抑制已经过时的提醒。每个 `todo/write` 事件都会重置计数，即使值完全相同；仅包含已完成项的清单会停用 epoch；`turn/start` 会在与 todo 投影相同的位置清除它。

`todo_write` 始终豁免。根级 `run_code` 也豁免，因为 Code Mode 只能通过该 transport 到达 `todo_write`；其带 parent 的 SDK 子调用才消耗预算。这样实际操作只计数一次，程序可以通过核对清单恢复，而且原生和 Code Mode agent 使用同一策略。没有 agent 的调用不存在 session 所属任务状态，不受该策略约束。

计数器只存在于进程内。首次观察会回扫当前 turn 最新的 `todo/write`，因此在未完成清单下挂载或恢复会启用强制机制，但恢复会给予一份新预算，而不会重建未记录的策略计数。

## 考虑过的替代方案

**只加强工具描述。** 否决：描述已经要求立即更新且不得批量完成；实际事件日志证明，仅靠指令不会产生缺失写入。

**从工具结果推断任务转换。** 否决：任务项与任意工具之间没有声明的归属关系，猜测会写入错误的持久事实。有界核对要求保留模型判断，同时让遗漏保持有限。

**扩展 `repeat-tool-reminder`。** 否决：完全相同调用的重复检测与 todo 新鲜度拥有不同的状态键、重置、豁免和强制语义。分离插件允许部署独立调整或移除任一策略，避免耦合两个无关启发式规则。

**阻断根级 `run_code`。** 否决：在 Code Mode 下，这会移除到达 SDK binding 以解除违规的唯一通路。对带 parent 的子调用计数既能强制工作，也能保留恢复路径。

**使用经过时间。** 否决：长工具运行期间没有模型 step 可以发起清单核对，计时器还会把慢 I/O 误判为状态过期。工具准入点才是 agent 能改选 `todo_write` 的位置。

## 后果

未完成清单不再只是被动 UI 元数据：它会约束后续工具准入。较长的单项工作必须按配置间隔写入不变心跳，增加少量上下文和工具调用成本，换取当前可观察状态。

guard 刻意不要求状态值发生变化。这既避免伪造进度，也允许确实较长的任务；每次确认只会开启另一个有界 epoch。首次写入未完成清单之前的工作不受影响。

原生 loop 测试固定提醒、拒绝、重置、全完成清单和释放行为；真实 Code Mode runtime fixture 固定根 transport 豁免和带 parent SDK 强制；Loader composition 测试固定必填配置；ACP 无密钥快照固定组装后 transcript 中带来源的提醒和拒绝结果。
